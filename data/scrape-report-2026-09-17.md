## Notes on this refresh

**Method.** First full run of the HTTP scraper (`scripts/scrape-sdmx.mjs`), replacing the Playwright wizard driver. 250 of 252 elements downloaded; `CALL_MONEY_RN` and `CLEARING_HOU_RN` fail in the portal's CSV exporter (HTTP 500, same in the browser) and their rows were kept as JSON under `data/sdmx-raw/json/` (8,682 and 195 rows). `data/sdmx/financial-sector/payment-systems/clearing-house.csv` is therefore the previous copy, not refreshed.

**What the 13,990 "removed" rows are.** A row counts as removed when today's download has no row with the same codes and period. Each one was classified (the FOOTNOTE attribute of two series contains commas and is parsed accordingly):

| Kind | Rows | Series |
|---|---|---|
| Aggregate rows coded `N_A` for a dimension the browser run left unselected | 12,793 | 24 |
| Same period and value, now under a corrected code or attribute | 1,105 | 12 |
| No longer published by RBI | 92 | 2 |

- **Aggregates.** The old wizard runs often failed to tick every value of a dimension, and the server then returned one row per period coded `N_A` for it. Checked numerically: treasury-bill outstanding totals equal the sum of the instrument-type rows; state agricultural production totals equal the new all-states rows; the forex-average and interest-rate `N_A` rows were arithmetic means of unrelated measures (for example a monthly-average rate and a month-end rate), so they were meaningless. The HTTP scraper groups by every code-list dimension, as the wizard does when every value is selected, so it cannot produce these rows. `N_A` is still a legitimate code in 19 series.
- **No longer published.** Central-government receipts no longer carries its two total lines, revenue receipts and total receipts (41 years each); each equals the exact sum of components that remain. The CPI annual-average table no longer carries the 2012-base all-India general index's annual variation for 2024-25, nor its annual average and variation for 2025-26. On 18-09-2026 the portal's own browser wizard returned exactly the rows the HTTP scraper returns for both series, with no difference in either direction, so this is a change at RBI after 02-07-2026, not a scraper difference.
- **History.** No series starts later or ends earlier than it did before. RBI revised 4,729 values in 50 series.

**Catalogue mapping bug (pre-existing, not fixed).** `data/catalogue.json` maps both annual exchange-rate files (`exchange-rate-of-indian-rupees-cy.csv` and `-fy.csv`) to `FOREX_RATE_A_RN`, because `data/build-catalogue.mjs` looks elements up by label and the two share one. The files themselves hold the right series.

**Longer history.** The old scraper capped look-back per frequency and fetched Daily series one month at a time; nine daily series were January 2011 stubs. The HTTP scraper takes full history (Daily from 2011-01-01), which is why many files grew substantially. The exchange-rates processor's reconciliation gate matched all 14,348 overlapping daily values against the RBI text base exactly.

**Downstream changes made so the pipeline passes on the refreshed data** (`pnpm data:build` and `pnpm data:verify`: ALL PASS, 104 checks):

- `data/processors/sdmx-series.mjs`: the agricultural anchor now looks up `COLD_STORG_CAP|ALL_INDIA|TN` (value unchanged, 38224006); the old key `…|N_A|…` was the artefact above.
- `data/processors/story-external-debt.mjs`: the government-debt series check requires the 1986–2026 span instead of exactly 41 rows (the source now starts in 1981); the 41 original rows are byte-identical.
- Oracles re-captured after checking every overlapping value was unchanged: `sdmx-agricultural-statistics-indian-state` (2 artefact columns → 72 real ones), `sdmx-average-forex-rate` (300 → 716 months, values identical), `sdmx-exchange-rate-of-the-indian-rupee-daily` (157 → 3,788 days, values identical), `sdmx-series-index` (5 series added, 63 end dates newer, none older), `story-external-debt`, `home` (USD/INR marker 01-Jul-2026 → 16-Sep-2026).
